# 第三方组件与许可清单

本文回答一个问题：**这个安装包里都有谁的东西，各自是什么许可，我们做了什么。**

最后更新：对应本包 `1.0.4`。

---

## 一、结论先说

| 项 | 结论 |
|---|---|
| 安装包里是否包含 RustFS 的二进制或镜像？ | **不包含。** 包里只有配置文件、脚本、图标和文档（几十 KB 到几 MB 级）。 |
| 运行时用的是什么镜像？ | `rustfs/rustfs:1.0.4`，**上游官方发布的镜像，我们不修改、不重建、不二次分发**。 |
| 我们改过上游代码吗？ | **没有。** 没有 fork、没有打补丁、没有编译。 |
| 本仓库自己的代码是什么许可？ | Apache-2.0。 |
| 有 copyleft（GPL/AGPL）义务吗？ | **没有。** 上游是 Apache-2.0。 |

## 三、Apache-2.0 带来的义务，以及我们怎么做

Apache-2.0 是宽松许可（无 copyleft），但仍有三条实质义务：

| 义务 | 我们怎么履行 |
|---|---|
| **保留版权与许可声明** | 仓库根目录保留 `LICENSE`（Apache-2.0 全文）与 `NOTICE`（归属声明）；包内 `manifest` 与应用内「关于」信息指向本仓库 |
| **修改过的文件要显著说明"被改过"** | 我们**没有修改上游任何文件**，因此没有这条义务。对本包自己的改动（容器运行参数、端口映射、数据目录约定、凭据注入方式）在 `NOTICE` 第三节逐条列明 |
| **商标不随代码授权** | `RustFS` 是 **RustFS, Inc.** 的商标。我们只在 README、应用描述、文档中用该词**指明所封装软件的来源**，不用于命名我方产品、不用其 Logo 做图标、不表示任何授权或背书 |

**关于"再分发镜像"**：Apache-2.0 允许再分发镜像，但需附带版权与许可声明。本项目选择**不分发镜像**（安装时拉取），因此这一层义务基本不触发；代价是用户安装时需要网络可达镜像仓库，这一点已在 README 与安装文档中如实说明。

## 四、如果将来上游许可变了怎么办

现实里会发生的事，先写清处理方式：

| 情况 | 我们会怎么做 |
|---|---|
| 上游换成 GPL/AGPL 类 copyleft 许可 | 重新评估本包的分发方式。届时「安装时拉取镜像」这一形态通常仍可行（不构成再分发），但会明确告知用户；若必须随包分发，则需一并满足源码提供义务，可能因此**停止分发**该版本 |
| 上游变更商标政策、要求改名或下架 | 按 `NOTICE` 第五节的承诺配合执行：改名、调整表述、停止分发相关版本 |
| 上游不再发布某个版本 | Releases 里保留历史包，但会在说明中标注「上游已不再维护该版本」，并建议升级 |
| 上游镜像被撤下 | 本包会随之失效（拉不到镜像）。我们会发布说明并提供替代版本号 |

## 五、你可以自己核对的事

```bash
# 1. 确认包里没有镜像/二进制（体积应该很小）
ls -lh rustfs-fnos-1.0.4-x86.fpk

# 2. 看包内是否有意外的第三方文件
tar -tzf rustfs-fnos-1.0.4-x86.fpk

# 3. 看应用实际使用的镜像与 tag（装好之后，在 NAS 上执行）
docker inspect --format '{{.Config.Image}}' <容器名>
```

第 3 步输出应当指向 `rustfs/rustfs:1.0.4` 这类上游镜像地址。如果你看到的是某个私人仓库的地址，那不是本项目的产物。
