# 数据放在哪：两种位置的差别（建议先读这一页）

RustFS 的对象数据（你存的备份、照片、文件）可以放在两个完全不同的地方。**装之前想清楚，装完再改也行，但改位置不会自动搬数据。**

---

## 一、两种位置的安全性对照

| | **A. 默认位置**（应用数据目录） | **B. 你自己指定的存储空间目录** |
|---|---|---|
| 实际路径 | `/vol<N>/@appdata/rustfs-fnos/data`（界面上显示为应用自己的 var 目录） | 你填的任意目录，例如 `/vol2/my-rustfs-data` |
| 安装时怎么选 | 向导里「数据存放目录」留空 | 向导里填完整路径 |
| **卸载（选保留数据）** | ✅ 数据保留 | ✅ 数据保留（卸载根本不碰它） |
| **卸载（选删除数据）** | ⚠️ 数据被删除 | ✅ **仍然保留** —— 卸载只处理应用自己目录里的东西 |
| **安装/升级失败触发回滚** | ⚠️ 有被一并清理的风险（真机实测：`@appdata` 与 `@appconf` 同一次消失） | ✅ 不受影响（不在应用目录里） |
| 空间大小 | 通常就是你装应用的那个空间，**很多人的系统/应用卷只有几十 GB** | 你自己挑，可以放在最大的那块盘上 |
| 换盘 / 扩容 | 要连应用一起折腾 | 直接指到新盘（只改指向，数据自己搬） |
| 文件管理器里能看到吗 | ❌ 一般看不到（在 `@appdata` 隐藏目录里） | ✅ 能，就在你建的普通目录里 |
| 备份脚本能找到它吗 | ✅ | ✅（`backup-data.sh` 会读 `settings.env` 里的 `DATA_DIR`） |
| 适合谁 | 只想试试、数据可有可无、空间够大 | **认真用、数据重要、盘多**（推荐） |

**一句话**：默认位置图省事，但**空间小、且有被回滚清理的风险**；把数据放到你自己的存储空间，卸载和失败回滚都动不到它。

> 注意一个常见误解：**「保留数据」这个选项只对默认位置有意义**。当数据在你自己的存储空间里时，卸载选「保留」还是「删除」都一样——程序根本不会去碰用户目录。

## 二、小白用户的动手路径（5 步）

> **关于权限（v9 起已定案）**：在「文件管理」里新建的目录**通常直接可用，不需要 sudo** —— fnOS 用 TrimACL 把目录授权给了应用用户（所以属主显示为 `admin` 也能写）。
> 只有两种例外会被拦下并给出**可直接粘的两条命令**（`chown` + `chmod`）：① 目录被显式设成应用不可写；② 目标路径的父目录不允许应用写入。详见 [docs/data-location-permissions.md](data-location-permissions.md)。


1. **装之前先看一眼盘**：打开「存储空间管理」，记住空间最大的那块盘（比如挂在 `/vol2`）。
2. **在「文件管理」里建一个专用目录**：在 `/vol2` 下新建 `my-rustfs-data`。
3. **安装时填三样东西**：
   - 管理员账号（默认 `admin`，可改）
   - 管理员密码（**自己定，≥8 位，记进密码管理器**）
   - 数据存放目录：填 `/vol2/my-rustfs-data`
     （**这一项可以留空——留空就用默认位置 `/vol<N>/@appdata/rustfs-fnos/data`**。
       默认位置随应用一起卸载、安装失败回滚时也可能被清理，且空间通常较小；
       想让数据更安全、更宽敞就填自己的目录。）
4. **装完点桌面图标进控制台**：地址形如 `http://<NAS的IP>:9201/rustfs/console/`，用第 3 步的账号密码登录，建第一个桶。
5. **卸载前**（如果哪天要卸）：先跑一次 `sudo bash scripts/backup-data.sh`。数据在你自己的盘上时，删不删应用都不影响它。

**忘记密码怎么办**：不用去翻文件——「应用中心 → RustFS → 设置」里直接填新账号密码保存即可（两个都填才生效）。

## 三、改数据目录会发生什么

**只改指向，不搬数据。** 改这个设置 = 告诉应用「以后往哪个文件夹写」，已经写好的东西不会跟着走。就像把相机的默认存盘目录从 A 改成 B，之前拍的照片仍然在 A 里。

### 会发生什么（实测）

1. 你在设置页把数据目录从默认位置改到一个自定义目录；
2. 应用把**原来的默认目录改名**成 `data.old-<时间戳>` 留在原地，**不删除任何内容**；
3. 新位置是一个空库 —— 你之前建的桶不在这里；
4. 如果这时又把设置改回「恢复默认位置」，应用会重建一个空的默认目录，**仍然读不到**原来那些桶。看上去像「数据没了」，其实它完整躺在 `data.old-<时间戳>` 里。

实测记录（`192.168.100.64`）：默认位置建的桶 `def-check` 在切换之后 `GetObject` 返回 **404**；与此同时 `data.old-20261027193301/` 里那个桶与它的对象都在（**21,379 字节**，未损坏）。

### 应用会先把命令打给你（v11 起）

执行「恢复默认位置」时，日志会列出所有 `data.old-*` 的**完整路径、体积、条目数**，并给出可直接粘的两条命令（样例见 [docs/upgrade-safety.md](upgrade-safety.md) 的对应一节）：

```
[rustfs-fnos] 旧数据目录（完整保留，未删除）：/vol1/@appdata/rustfs-fnos/data.old-20261027193301　体积 21K，条目 2
[rustfs-fnos]   sudo cp -a "/vol1/@appdata/rustfs-fnos/data.old-20261027193301/." "/vol1/@appdata/rustfs-fnos/data/"
[rustfs-fnos]   sudo chown -R 996:901 "/vol1/@appdata/rustfs-fnos/data"
```

日志里 `chown` 用的是 **uid:gid**（如 `996:901`，取自你这台机器）；下面手写命令用的是**用户名:组名**（`rustfs-fnos:rustfs-fnos`）——**两者等价**，用哪个都行。

### 自己动手搬回来（可直接粘）

```bash
# 1) 先在应用中心把应用【停止】（不是卸载）
# 2) 看清楚有几个、分别叫什么
ls -d /vol*/@appdata/*/data.old-*
# 3) 把旧库内容复制回默认目录（把 <时间戳> 换成上一步列出来的那个）
sudo cp -a /vol<N>/@appdata/rustfs-fnos/data.old-<时间戳>/. /vol<N>/@appdata/rustfs-fnos/data/
# 4) 修正归属（容器以应用用户运行；用户名以你设备上 ls -ld 看到的为准）
sudo chown -R rustfs-fnos:rustfs-fnos /vol<N>/@appdata/rustfs-fnos/data
# 5) 回应用中心 → 启动，然后到控制台确认桶与文件都在
```

三点要说明：

- **`/vol<N>` 是占位**：`/vol1` 是第一个存储空间，数据在别的卷上时可能是 `/vol2`、`/vol3`。第 2 步那条 `ls -d /vol*/@appdata/*/data.old-*` 会一次列全。
- **`cp -a <源>/. <目标>/` 结尾那个 `/.` 不能省。** 它的意思是「把源目录**里面的内容**复制进目标目录」；写成 `cp -a <源> <目标>/` 会变成 `<目标>/<源目录名>/`，多套一层，控制台里还是看不见数据。
- **用 `cp -a`，不要用 `mv`。** `cp -a` 保留时间戳与权限；复制成功、确认数据对了再删旧的，才有回头的余地。

### 搬完确认没问题，再清掉旧目录

```bash
# 只在确认桶与文件都在、且应用运行正常之后执行
sudo rm -rf /vol<N>/@appdata/rustfs-fnos/data.old-<时间戳>
```

### 为什么不是「自动搬过去」

两个原因：一是搬动大目录很慢（几十 GB 到几 TB 可能几十分钟），中途断电或空间不足会留下半份数据，而且事后很难判断「哪一份才是对的」；二是应用分不清你是「想让数据搬过去」还是「只想换个地方重新开始」。所以它只做最安全的那一半：**改名保留、一字节不删**，搬运这一步交给你决定——而且现在会连命令一起打给你。

### 以后怎么避免这件事

| 情况 | 做法 |
|---|---|
| 本来就想放自己的大盘 | **第一次安装时就把数据目录设到大容量存储空间**（向导里选「改到下面填写的目录」）。之后不需要再切，也就不会有搁浅目录 |
| 已经装在默认位置、想换盘 | 切换前先把默认目录里的桶列出来记下（或截图）；切换后按上面的命令把旧库搬进新位置 |
| 只是想换位置、旧数据两边都不要 | 同上，搬完确认后再删旧目录 |
| 任何时候 | **先停应用再动目录**。运行中复制出来的数据可能不一致 |

> 一句话记住：**改数据目录只改「以后写到哪」，不改「已经写在哪」；旧目录会变成 `data.old-<时间戳>`，不会消失，但也不会自动跟过去。**

## 四、为什么不能让数据目录随便填

程序会拒绝这些位置（并给出可读原因）：

| 拒绝的位置 | 原因 |
|---|---|
| `/`、`/etc`、`/usr`、`/bin`、`/boot`、`/dev`、`/proc`、`/sys`、`/root`、`/run` | 系统目录，写进去会破坏系统 |
| `/tmp` | 重启后可能被清空 |
| `/var` 与程序安装目录 | 应用自己的地盘，升级/卸载都可能动它 |
| `/vol1`（整个存储空间的根） | 应该建子目录，例如 `/vol1/my-rustfs-data` |
| 其它应用的 `@appdata` / `@appconf` / `@appmeta` / `@apptemp` | 那是别的应用的数据，且会被它们的卸载/回滚影响 |
| 不可写、剩余空间不足的目录 | 直接失败，避免装完写不进数据 |

## 五、Docker 怎么找到那块盘（给排查用）

界面上的挂载点永远是应用自己的 `var/data`，它可能是一个**符号链接**：

```bash
# 看真实位置（不是链接就说明用的是默认位置）
sudo readlink -f /var/apps/rustfs-fnos/var/data

# 看应用记录的设置
sudo cat /var/apps/rustfs-fnos/etc/settings.env | grep DATA_DIR
```

这样做是因为 compose 读不到应用的设置文件，只能固定挂载一个稳定路径；换目录就等于换链接，几秒完成，容器也无需改配置。
